# Ankrからの移行

:::caution 日没のお知らせ

**Ankr**におけるKaiaのサポートは、**2026年10月16日**をもって終了します。その日付以降、Kaiaチェーンを指すすべてのAnkr RPCエンドポイントは運用を終了し、応答しなくなります。

お使いのアプリがAnkrにKaia RPC呼び出しを行っている場合は、サービス終了日までに別のプロバイダーに切り替えてください。ほとんどのプロジェクトでは、エンドポイントの変更は1行で済みます。詳しくは [代替案の選択](#choose-an-alternative) をご覧ください。

:::

## 何が変化しているのか

Ankrは、Kaia RPCサービスの提供を終了します。これはエンドポイントにのみ影響するものであり、Kaia自体には何の変化もありません。

| 日付              | どうなるのか                                                           |
| --------------- | ---------------------------------------------------------------- |
| **2026年10月16日** | Kaiaチェーン向けのAnkr RPCエンドポイントはすべて運用を終了しました。リクエストがデータを返さなくなりました。     |
| 日没の後            | KaiaはAnkrでは利用できなくなりました。既存のAPIキーおよびプランでは、Kaiaのトラフィックに対応できなくなりました。 |

**影響を受けないもの：**

- Kaiaメインネット（8217）およびKairosテストネット（1001）そのもの
- お客様の契約、アドレス、残高、およびオンチェーン履歴
- Ankrを呼び出さないアプリのどの部分でも

すべてのRPCプロバイダーは、同じチェーンデータを提供します。アプリを別のエンドポイントに指定しても、同じ結果が返されます。

## あなたも影響を受けていますか？

以下のいずれかに該当する場合、影響を受けます：

- アプリ、スクリプト、またはCIから、`rpc.ankr.com` 配下のホストに対して、KaiaへのJSON-RPC呼び出しが行われます。
- Ankrという名前のプロジェクト内のウォレット設定、Hardhat/Foundryネットワークのエントリ、またはSDKプロバイダーのURL。
- スタック内の依存関係、インデクサー、ダッシュボード、または分析ジョブが、Ankrを介してKaiaからデータを読み取ります。

コードベースを素早く確認する方法：

```bash
grep -rn "ankr" --include="*.ts" --include="*.js" --include="*.json" --include="*.toml" --include="*.yaml" --include="*.yml" --include="*.env*" .
```

また、grepでは検出できない場所についても確認してください。具体的には、デプロイ環境変数、CI/CDのシークレット、サーバーレス関数の設定、およびウォレットやホスト型ダッシュボードに保存されているRPC URLなどです。

すでにKaia Foundationのパブリックエンドポイントや他のプロバイダーをご利用の場合は、**影響を受けません**。

:::tip 2026年10月16日までにこれを行ってください

Ankrアカウントがまだ有効な間は：

- プロジェクトで使用しているAnkrのエンドポイントとAPIキーをメモしておき、更新が必要な箇所をすべて特定できるようにしておきましょう。
- Ankrのダッシュボードから、保存しておきたい利用状況や分析データをエクスポートしてください。
- 移行が完了したら、Ankrのサブスクリプションを解約してください。そうすれば、もう利用していないサービスに対して請求されることはありません。

:::

## 別の選択肢を選んでください

以下の医療提供者はすべて、本日カイアを担当しています。これらはすべて同じJSON-RPCインターフェースを採用しているため、移行にあたってはコードの変更ではなく、URLの変更だけで済みます。

|                | [錬金術](https://www.alchemy.com/rpc/kaia) **(おすすめ)** | [QuickNode](https://www.quicknode.com/docs/kaia) | [All That Node](https://www.allthatnode.com/) | [dRPC](https://drpc.org/) | カイア財団     |
| -------------- | --------------------------------------------------------------------- | ------------------------------------------------ | --------------------------------------------- | ------------------------- | --------- |
| **ホスティング**     | 管理対象                                                                  | 管理対象                                             | 管理対象                                          | 管理対象                      | 一般向け、地域主導 |
| **APIキーが必要です** | はい                                                                    | はい                                               | はい                                            | いいえ、パブリックエンドポイントの場合は      | いいえ       |
| **移行作業**       | URLを入れ替える                                                             | URLを入れ替える                                        | URLを入れ替える                                     | URLを入れ替える                 | URLを入れ替える |
| **おすすめ**       | 最も多い移行                                                                | 専用のエンドポイントを必要とする本番用アプリ                           | NodeとFaucetのツールを希望するチーム                       | 最速のスタート、登録不要              | 開発とテスト    |

アーカイブの履歴や `debug` / `trace` ネームスペースなどの機能は、プロバイダーやプランによって異なります。導入を決定する前に、プロバイダーが提供するドキュメントを参照し、ご自身のワークロードに必要な要件を確認してください。表の見出しにあるリンクは、それぞれに関する信頼できる情報源です。

**Ankrから移行するほとんどのチームにとって、Alchemyが推奨される代替手段です。**

エンドポイントのURL、およびKaiaに対応するRPCプロバイダーの完全な一覧については、[公開JSON RPCエンドポイント](./public-en.md)を参照してください。お好みのプロバイダーに登録し、アプリ内のAnkrのURLを、そのプロバイダーから提供されたエンドポイントに置き換えてください。

ホスティングプロバイダーに一切依存したくない場合は、[独自のエンドポイントノードを運用する](../nodes/endpoint-node/endpoint-node.md)ことも可能です。
