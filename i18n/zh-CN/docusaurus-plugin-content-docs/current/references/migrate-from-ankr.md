# 从 Ankr 迁移

:::caution 终止服务通知

**Ankr** 上对 Kaia 的支持将于 **2026 年 10 月 16 日** 终止。该日期之后，所有指向 Kaia 链的 Ankr RPC 端点都将停止运行，并停止响应。

如果您的应用向 Ankr 发送 Kaia RPC 调用，请在停用日期之前切换到其他服务提供商。对于大多数项目而言，这只需修改一行端点代码即可——请参阅 [选择替代方案](#choose-an-alternative)。

:::

## 有哪些变化

Ankr 将停止提供其 Kaia RPC 服务。这仅影响端点——Kaia 本身没有任何变化。

| 日期              | 会发生什么                                         |
| --------------- | --------------------------------------------- |
| **2026年10月16日** | 所有针对 Kaia 链的 Ankr RPC 端点均已停用。请求不再返回数据。        |
| 日落之后            | Kaia 已无法通过 Ankr 获取。现有的 API 密钥和套餐不再支持 Kaia 流量。 |

**不受影响的内容：**

- Kaia 主网 (8217) 和 Kairos 测试网 (1001) 本身
- 您的合约、地址、余额和链上交易记录
- 您应用中任何未调用 Ankr 的部分

每个 RPC 提供者都提供相同的链数据。将您的应用指向另一个端点也会返回相同的结果。

## 您是否受到影响？

如果符合以下任一情况，您将受到影响：

- 您的应用、脚本或持续集成（CI）会向 `rpc.ankr.com` 下的主机发送 Kaia JSON-RPC 调用。
- 在您的 Ankr 项目中，钱包配置、Hardhat/Foundry 网络条目或 SDK 提供商 URL。
- 您技术栈中的某个依赖项、索引器、仪表盘或分析任务通过 Ankr 读取 Kaia 数据。

快速检查代码库的方法：

```bash
grep -rn "ankr" --include="*.ts" --include="*.js" --include="*.json" --include="*.toml" --include="*.yaml" --include="*.yml" --include="*.env*" .
```

此外，还请检查 grep 无法触及的位置：部署环境变量、CI/CD 密钥、无服务器函数配置，以及保存在钱包或托管仪表板中的任何 RPC URL。

如果您已经使用 Kaia Foundation 的公共端点或其他提供商的服务，则**不会**受到影响。

:::tip 请在2026年10月16日之前完成此操作

在您的 Ankr 账户仍处于活跃状态期间：

- 请记录下您的项目所使用的 Ankr 端点和 API 密钥，以便您能找到所有需要更新的地方。
- 从 Ankr 仪表盘中导出您希望保留的任何使用情况或分析数据。
- 完成迁移后，请取消您的 Ankr 订阅，以免因不再使用的服务而被收费。

:::

## 选择其他选项

以下所有医疗服务提供者今天都在为凯亚提供服务。由于它们都采用相同的 JSON-RPC 接口，因此迁移只需更改 URL，而无需修改代码。

|               | [炼金术](https://www.alchemy.com/rpc/kaia) **(推荐)** | [QuickNode](https://www.quicknode.com/docs/kaia) | [All That Node](https://www.allthatnode.com/) | [dRPC](https://drpc.org/) | 凯亚基金会      |
| ------------- | ------------------------------------------------------------------- | ------------------------------------------------ | --------------------------------------------- | ------------------------- | ---------- |
| **主机服务**      | 托管                                                                  | 托管                                               | 托管                                            | 托管                        | 公共的、由社区运营的 |
| **需要 API 密钥** | 是的                                                                  | 是的                                               | 是的                                            | 不，对于公共端点                  | 不          |
| **迁移工作**      | 替换 URL                                                              | 替换该网址                                            | 替换该网址                                         | 替换 URL                    | 替换 URL     |
| **最适合**       | 大多数迁移                                                               | 需要专用端点的生产环境应用                                    | 希望获得节点和水龙头工具的团队                               | 快速入门，无需注册                 | 开发与测试      |

诸如归档历史记录以及 `debug` / `trace` 命名空间等功能因提供商和套餐而异。在做出决定之前，请查阅服务商提供的文档，了解您的工作负载有哪些需求——表格标题中的链接是各项目的权威来源。

对于大多数不再使用Ankr的队伍来说，**Alchemy是推荐的替代方案**。

有关端点 URL 以及为 Kaia 提供服务的 RPC 提供商的完整列表，请参阅 [公共 JSON RPC 端点](./public-en.md)。在您选择的服务商处注册，然后将应用中的 Ankr URL 替换为该服务商提供的端点。

如果您完全不想依赖托管服务提供商，也可以[运行自己的端点节点](../nodes/endpoint-node/endpoint-node.md)。
