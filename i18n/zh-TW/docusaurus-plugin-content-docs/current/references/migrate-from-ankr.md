# 從 Ankr 遷移

:::caution 日落通知

**Ankr** 對 Kaia 的支援將於 **2026 年 10 月 16 日** 結束。自該日期起，所有指向 Kaia 鏈的 Ankr RPC 端點將被停用並停止回應。

若您的應用程式會向 Ankr 發送 Kaia RPC 呼叫，請在停用日期前切換至其他服務供應商。對於大多數專案而言，這只需對終點進行一行修改即可——請參閱 [選擇替代方案](#choose-an-alternative)。

:::

## 有哪些變化

Ankr 將停止提供 Kaia RPC 服務。這僅會影響端點——Kaia 本身並無任何變更。

| 日期              | 會發生什麼事                                         |
| --------------- | ---------------------------------------------- |
| **2026年10月16日** | 所有針對 Kaia 鏈的 Ankr RPC 端點均已停用。請求不再傳回資料。         |
| 日落之後            | Kaia 已無法透過 Ankr 取得。現有的 API 金鑰和方案不再支援 Kaia 的流量。 |

**不受影響的項目：**

- Kaia 主網 (8217) 及 Kairos 測試網 (1001) 本身
- 您的合約、地址、餘額及鏈上交易紀錄
- 您應用程式中任何未呼叫 Ankr 的部分

每個 RPC 提供者所傳遞的鏈資料都相同。將您的應用程式指向不同的端點，會返回相同的結果。

## 您是否受到影響？

若符合以下任一情況，您即受此影響：

- 您的應用程式、腳本或持續整合（CI）會向 `rpc.ankr.com` 下的某個主機發送 Kaia JSON-RPC 呼叫。
- 您的 Ankr 專案中包含的錢包設定、Hardhat/Foundry 網路條目或 SDK 提供者網址。
- 您技術堆疊中的某個依賴項、索引器、儀表板或分析工作會透過 Ankr 讀取 Kaia。

快速檢查您的程式碼庫的方法：

```bash
grep -rn "ankr" --include="*.ts" --include="*.js" --include="*.json" --include="*.toml" --include="*.yaml" --include="*.yml" --include="*.env*" .
```

同時也請檢查 `grep` 無法觸及的位置：部署環境變數、CI/CD 機密資訊、無伺服器函式設定，以及儲存於錢包或託管儀表板中的任何 RPC URL。

如果您已經使用 Kaia Foundation 的公開端點或其他供應商，則您將**不受**此影響。

:::tip 請在 2026 年 10 月 16 日之前完成此事項

在您的 Ankr 帳戶仍處於活躍狀態時：

- 請記錄您的專案所使用的 Ankr 端點和 API 金鑰，以便您能找出所有需要更新的位置。
- 從 Ankr 儀表板中匯出您想保留的任何使用情況或分析資料。
- 完成系統切換後，請取消您的 Ankr 訂閱，以免因不再使用的服務而被收費。

:::

## 選擇其他選項

以下所有醫療服務提供者今日均為凱亞提供服務。由於它們都採用相同的 JSON-RPC 介面，因此遷移只需變更 URL，無需修改程式碼。

|                | [煉金術](https://www.alchemy.com/rpc/kaia) **(推薦)** | [QuickNode](https://www.quicknode.com/docs/kaia) | [All That Node](https://www.allthatnode.com/) | [dRPC](https://drpc.org/) | 凱亞基金會   |
| -------------- | ------------------------------------------------------------------- | ------------------------------------------------ | --------------------------------------------- | ------------------------- | ------- |
| **主機服務**       | 受管理                                                                 | 受管理                                              | 受管理                                           | 受管理                       | 公共、社區營運 |
| **需提供 API 金鑰** | 是的                                                                  | 是的                                               | 是的                                            | 不，針對公開端點                  | 不       |
| **遷徙行動**       | 交換 URL                                                              | 交換網址                                             | 交換 URL                                        | 交換 URL                    | 交換 URL  |
| **最適合**        | 大多數的遷移                                                              | 需要專用端點的生產環境應用程式                                  | 希望取得 Node Plus Faucet 工具的團隊                   | 最快上手，無需註冊                 | 開發與測試   |

諸如存檔歷史紀錄以及 `debug` / `trace` 命名空間等功能，會因服務供應商及方案而異。在做出決定之前，請查閱服務供應商自身的文件，以確認您的工作負載有哪些需求——表格標題中的連結即是各服務的權威參考來源。

對於大多數正從 Ankr 轉移陣容的隊伍而言，**Alchemy 是推薦的替代方案**。

有關端點 URL 以及為 Kaia 提供服務的 RPC 供應商完整清單，請參閱 [公開 JSON RPC 端點](./public-en.md)。請向您選擇的服務提供商註冊，然後將應用程式中的 Ankr URL 替換為該服務提供商提供的端點。

如果您完全不想依賴託管服務提供商，也可以 [自行運行端點節點](../nodes/endpoint-node/endpoint-node.md)。
